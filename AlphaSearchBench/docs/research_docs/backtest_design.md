## 0. 한 장 요약

```
                    [입력 계약]  수식 목록(필수) + 방향/가중/native 결합 명세(선택)
                         │
       ┌─────────────────┴──────────────────┐
  Common 트랙 (본선)                   Native 트랙 (참고선)
  표준 프로토콜 세트 ASB-P1.0 동결        각 방법의 결합법 명세대로
  (결합 2 × 매매규칙 3 × 비용 2 = 12셀)   (명세 없으면 생략)
       │                                    │
  전 셀 성과표 + 프로파일                    같은 그래프에 점선
  (중앙값 / 최악 셀 / DCS)                  (시스템 성능으로 라벨)
       │                                    │
       └───── Combiner Lift = Native − Common ─────┘
  순위·Q4 상관분석은 Common에서만        Lift 자체가 분석 대상
```

**핵심 문장**: ASB의 backtest는 "최선의 전략 하나"가 아니라 **사전 동결된
표준 프로토콜 격자 위의 성과 분포**로 alpha pool을 측정하는 도구다. 방법별
고유 결합법은 제거하지 않고 별도 트랙으로 측정하며, 두 트랙의 차이(Combiner
Lift)를 새로운 분석 대상으로 삼는다.

## 1. 설계 철학

### 1.1 Backtest는 전시장이 아니라 측정기구다

본 연구의 목적(Q4)은 "pool의 QD 특성이 OOS·포트폴리오 성능과 연결되는가"의
검정이다. 포트폴리오 성능은 그 검정의 **종속변수**이므로, backtest 층의 설계
기준은 "수익을 잘 내는 전략"이 아니라 **"pool 간 차이를 왜곡 없이 드러내는
측정"**이다. 이 관점 전환이 이후 모든 결정의 뿌리다.

### 1.2 근본 문제 — 성능 = 재료 × 요리법, 그리고 유일한 공정 요리법은 없다

모든 alpha mining 논문의 최종 성능은 다음의 곱이다:

```
발견한 수식들(재료) × 결합 방법(combiner) × 매매 규칙(portfolio rule) × 비용 가정
```

각 논문은 뒤의 세 요소를 자기에게 맞게 고른다 — AlphaAgent(KDD'25)는
LightGBM(depth 4) 결합 + qlib TopkDropout(top-50/drop-5) 롱온리 + 비대칭
비용(매수 5bps/매도 15bps), AlphaGen은 자체 선형 결합 + top-k 교체 제한,
AlphaEval repo 원형은 DE 최적화 가중 + 분위 20/20 롱숏 + 무지연 체결이다
(전부 논문 PDF·코드 직독으로 확인, §7 근거표). 따라서 최종 수익만 비교하면
**재료가 좋았는지 요리 솜씨가 좋았는지 식별 불가능**하다.

동시에, "유일하게 공정한 공통 요리법"은 존재하지 않는다. 우리의 E3 실측(§6)이
보여주듯 **프로토콜 선택은 pool 순위를 바꾼다** — 어떤 단일 선택도 특정
성격의 pool(저회전/고회전, 집중형/분산형)에 유리하다. 그러므로 공정성은
"올바른 하나를 고르는 것"이 아니라 다음 세 가지로 달성한다:

1. **동일 적용** — 모든 pool에 완전히 같은 프로토콜 집합을 적용한다.
2. **복수 프로토콜** — 소수의 표준 프로토콜 **세트**를 쓰고 전 결과를 공개해,
   프로토콜 민감도 자체를 측정값으로 만든다.
3. **역할 명시** — 각 프로토콜이 어떤 질문에 답하는지(위험 관점/비용 관점/
   논문 비교 관점)를 설계 문서에 못 박는다.

### 1.3 세 층위의 질문을 섞지 않는다

| 층위 | 질문 | 담당 |
|---|---|---|
| L1 Native-protocol | "그 논문의 배치층 아래에서 성능은?" | Native 트랙 (참고선) |
| L2 Standardized Pool | "동일 배치 규칙 아래에서 어느 pool이 유용한가?" | **Common 트랙 (본선)** |
| L3 Controlled Search | "동일 공간·목적함수·예산에서 탐색 연산자(GP/RL/LLM) 자체의 차이는?" | 별도 실험(패리티 하네스), backtest 설계 범위 밖 |

주장 문구도 층위를 따른다. ❌ "GP가 AlphaAgent보다 우수하다" →
✅ "두 방법이 생성한 pool을 동일 배치 규칙에서 평가했을 때 A가 B보다 높은
OOS/포트폴리오 유용성을 보였다".

주의: L1을 "Native Reproduction"이라 부르지 않는다. 완전 재현은 대부분
불가능하다 — AlphaAgent 논문은 정규화 계수(λ, α₁₋₃, β₁₋₃)·프롬프트를
비공개했고 공식 repo는 다른 시스템으로 재작성되었으며, AlphaEval repo
원형에는 결과를 바꾸는 버그(HOF anti-selection, 첫날 NaN 비용, 죽은
threshold 인자)가 있다. 가능한 것은 **배치층만의 재현(native-protocol)**이다.

## 2. Common 트랙 — 표준 프로토콜 세트 ASB-P1.0

### 2.1 격자 정의 (2 × 3 × 2 = 12셀)

| 축 | 값 | 선택 근거 |
|---|---|---|
| **① Combiner** | (a) equal-weight z-score 합 (현행) | 가장 단순·무학습 — pool 결함이 성과에 그대로 비침(§2.4) |
| | (b) **train-부호 보정** equal-weight | (a)는 부호를 흡수하지 못해 음IC factor가 pool을 희석. 방향 미정의 pool(Alpha101/158)은 (b) 없이는 결합 자체가 무의미 |
| **② Portfolio rule** | (A1) 분위 20/20 롱숏, 매일, gross 1 | 시장중립 위험 관점. ASB v0.1 계약(AlphaEval repo 계보) |
| | (A2) top-50 롱숏, 5일 보유 | 회전 상한 관점 — 비용 민감도를 구조로 분리 |
| | (A3) qlib TopkDropout top-50/drop-5 **롱온리**, 지수 대비 초과 AR·IR | **논문 anchor** — AlphaAgent(KDD'25) §4.1.2와 동일 배치층. 참고연구 수치와 직접 비교 가능한 유일한 셀 |
| **③ Cost** | 0bps / 15bps(편도 L1 기준) — A3 셀은 논문 그대로 매수 5bps/매도 15bps | "옳은 비용" 논쟁을 스윕으로 흡수. 0bps 셀이 gross/net 분해를 격자에 내장 |

**고정 항목(축이 아님)**: 체결 `next_open`(t 종가 신호 → t+1 시가; 무지연
`same_close`는 낙관 편향으로 본 격자에서 제외 — repo 대조가 필요할 때만
부록 셀), universe·PIT 멤버십 마스크·label(1일 forward)·회전 정의(편도
L1=½Σ|Δw|)·첫날 건립 비용 부과·연환산 규약(√252, ddof=1)은 전 셀 동일.
split은 train 2010–2019(=마이닝 창) / valid 2020 / test 2021–2024
(참고연구 2편과 동일 구조, valid는 마이닝 창 밖 — 오염 없음).

### 2.2 프로토콜 버전 동결 (범용성의 핵심 장치)

위 격자를 **ASB-P1.0**으로 명명하고 동결한다. 이후 등장하는 임의의 pool
(AlphaGen, AlphaQCM, QuantaAlpha, 미래의 방법)도 같은 버전으로 평가하면
오늘의 결과와 직접 비교된다 — 고정 test set이 벤치마크를 벤치마크로 만드는
것과 같은 원리다. 격자 변경(축 추가·셀 교체)은 반드시 버전 증가(P1.1, P2.0)와
변경 근거 문서를 동반하며, 새 버전 도입 시 기존 pool 전체를 재평가해
버전 간 대조표를 남긴다. **축 추가의 채택 기준**: "그 축이 pool 순위를
바꾼다는 실측 증거"가 있을 때만 (E3가 프로토콜 축에 대해 그랬듯).

### 2.3 보고 형식 — 점이 아니라 프로파일

pool마다 12셀 성과 전체(롱숏 셀: net Sharpe·MDD·회전율, 롱온리 셀:
초과 AR·IR·MDD)를 표로 공개하고, 요약은 세 값으로 한다:

* **중앙값 성과** — 12셀 중앙값. 프로토콜 행운에 둔감한 대표값.
* **최악 셀 성과** — worst-case. 실무적 하한.
* **DCS (Deployment Consistency Score)** — 흑자 셀 비율(롱숏: Sharpe>0,
  롱온리: 초과AR>0). "이 pool은 12가지 배치 중 몇 개에서 살아남는가."
  특정 프로토콜에서만 반짝하는 pool(운)과 어디서든 되는 pool(강건)을 구분.

DCS는 셀들이 독립 표본이 아니므로 **기술 지표**로만 쓴다(신뢰구간 없음).

### 2.4 왜 Common 결합기는 단순해야 하는가

결합기가 똑똑할수록(LightGBM, 동적 가중) 나쁜 재료를 학습으로 보정해
**pool 품질과 결합기 품질이 다시 섞인다** — 분리하려던 것이 되돌아온다.
또한 Q3(pool 구조)–Q4(성능 연결) 분석은 pool의 구조적 특성(다양성, 부호
일관성, 상관)이 성과에 그대로 비쳐야 성립한다. 모델 결합기는 그 연결을
끊는다. 따라서 Common 트랙은 무학습 결합만 쓰고, "모델이 pool을 구제할 수
있는가"는 Native 트랙/부록의 질문으로 넘긴다.

### 2.5 Pool 크기 문제 (n_factors 불균형)

GP pool은 10개, Alpha101은 101개다. 등가중 결합은 큰 pool에 분산 효과만으로
유리하다. 이중 보고로 해결한다:

* **기본: 제출된 그대로(as-submitted)** — pool 크기도 방법의 산출물이다.
  `n_factors`를 모든 표에 병기.
* **보조: 크기 통제판(size-controlled)** — 각 pool에서 **valid 분할** IC
  상위 K(기본 10)개만 뽑아 재평가. 선택에 test 사용 금지(§4-2).

## 3. Native 트랙 — 존중하되, 측정 대상으로

### 3.1 정의

pool 제출 시 **native 결합 명세**(결합 알고리즘 + 하이퍼파라미터)가 함께
오면, 그 명세대로도 평가해 **같은 그래프에 점선**으로 겹쳐 그린다. 라벨은
"시스템 성능(system)"이며 방법 간 순위 주장에는 쓰지 않는다.

### 3.2 구현 가능성 실사 (2026-08 기준)

| 방법 | native 결합 | 논문/코드에서 구현 가능? | 충실도 주석 |
|---|---|---|---|
| AlphaEval repo GP | DE 최적화 IC-가중(Σ\|w\|=1) | 가능 — 단 원본 `combo.py`는 maxiter=1·seed 없음(비재현) → **seed 고정·iter 정상화 후** 사용, 편차 명시 | 원본 그대로는 실행마다 다른 가중 |
| AlphaGen | 결합모델 IC를 보상으로 학습한 선형 가중 | 가능(gradient-fit 선형) | pool이 이 결합 전제로 학습됨 — Lift가 클 것으로 예상 |
| AlphaForge | 동적 선택+동적 가중(mega-alpha) | 가능(논문 기술 수준) | 시변 가중 — 시점 규약 명시 필요 |
| AlphaAgent | 4 base alpha + 채굴 alpha → LightGBM(depth 4) | **부분 가능** — 모델 구조·base alpha는 공개, 탐색 정규화 계수는 비공개(마이닝 쪽 문제라 결합 재현엔 무관) | 예측→신호 변환 규약 명시 |
| Alpha101/158 (static) | 없음 | — | Common 트랙 전용 |

### 3.3 Combiner Lift — 균형을 넘어 발견으로

두 트랙을 병렬 전시로 끝내지 않고 차이를 지표화한다:

```
Combiner Lift(method, cell) = Native 성과 − Common 성과   (동일 매매규칙·비용 셀에서)
```

해석: Lift가 크면 "그 방법의 가치는 수식보다 결합기에 있다", ~0이면 "수식
자체가 좋다", 음수면 "고유 결합기가 오히려 해롭다". AlphaGen처럼 결합 전제로
탐색한 방법은 큰 Lift가 **예측**되며, 실측되면 그 자체가 벤치마크의 발견이다.
Native 트랙은 이로써 "예우용 부록"이 아니라 측정 대상이 된다.

## 4. 무결성 규칙 (격자가 체리피킹 도구가 되지 않도록)

12개 숫자는 좋은 것만 인용하면 오히려 p-hacking 도구다. 다음을 규칙으로
동결한다:

1. **전 셀 보고 의무** — 어떤 주장이든 12셀 표 전체가 딸려간다. 특정 셀 인용
   시 셀 좌표(결합·규칙·비용)를 명시한다.
2. **선택은 valid, 보고는 test** — pool별 파라미터 선택이 필요한 모든 경우
   (크기 통제판의 top-K 등) 선택은 valid(2020)에서, 보고는 test(2021–24)에서.
3. **판독 규칙 사전 등록** — 실험 전에 "무엇이 나오면 무슨 결론"을 계획
   파일에 고정한다(E3의 결정 게이트 방식).
4. **gross/net 상시 분해** — 0bps 셀과 유비용 셀의 차 = 비용 드래그.
   손실의 원인(신호 부재 vs 비용)이 격자 안에서 자동 식별된다.
5. **부호 정책 명시** — 결합기 (b)의 방향은 train 창 IC 부호로만 유도
   (기존 train_sign 규약 재사용). test 정보 사용 금지.
6. **음성 결과 동등 보고** — 전 셀 손실인 pool도 동일 형식으로 기록한다
   (그것이 "신호 부재"라는 결과다 — E3의 \|IC\| 계열이 실례).
7. **조용한 유실 금지** — 평가 불가 수식·gate 탈락·빈 pool은 제외 사유와
   개수를 함께 기록한다(`n_gated_out`, `skip_reason`, `empty_pool`).

## 5. 입력 계약 (범용성)

벤치마크의 범용성은 프로토콜이 아니라 **입구 규격**에서 나온다. "이 계약만
지키면 임의의 미래 pool도 평가 가능"으로 정의한다:

* **필수**: 수식 문자열 목록(`final_pool_*.csv`의 `formula` 열). qlib 표현식
  문법 기준이며, 2단 신호 엔진(자체 FormulaEngine → qlib native fallback)이
  방언을 흡수한다. 미해석 수식은 사유와 함께 기록·제외(조용한 유실 금지).
* **선택**: factor별 방향(train_sign), factor별 가중, **native 결합 명세**,
  탐색 trajectory(있으면 search-QD 분석 대상이 됨).
* **카테고리 라벨**: `mined`(GP/RL/LLM 산출) vs `static_reference`
  (Alpha101/158 등 인간 설계) — 같은 격자로 평가하되 표에서 구분.
* RPN·AST 등 다른 표현의 pool은 표현식 문자열로 변환하는 어댑터를 제출
  측에서 제공하거나 ASB에 기여한다(AlphaGen/AlphaQCM은 변환 가능 확인).

## 6. 이 설계를 강제한 실측 근거

설계는 취향이 아니라 이 저장소에서 측정된 사실들의 귀결이다:

1. **프로토콜이 순위를 바꾼다** (E3, 29 pool × 4 arm): fbfit pool은
   A1 +7.7% → A3 초과 +17.2%/IR 1.29(논문 CSI500 대역 도달), \|IC\| pool은
   회전을 159→23배로 눌러도 전부 음수. 단일 프로토콜 보고는 이 상호작용을
   숨긴다 → 격자 필요.
2. **비용 드래그와 신호 부재는 분리 가능하고, 분리해야 한다**: \|IC\| pool의
   연회전(편도) 96~193배 × 15bps = 연 14~29%p 소실, 그러나 gross도 ~0.
   → 0bps 셀 내장 필요.
3. **결합기는 중립이 아니다**: fbfit 3-수식 pool은 +17.2%, 같은 run을 10개로
   다양화(fixedhof)하면 −3.0% — 등가중 결합은 집중형/균질형 pool의 순위를
   결합기 특성만으로 뒤집을 수 있다 → 결합기를 축으로 승격 + Lift 지표.
4. **"원본 그대로"는 공정의 보증이 아니다**: repo 원형 프로토콜(A4)은 4-arm
   중 최악(무지연 체결의 낙관보다 l1 왕복 비용이 지배), 원형 HOF는
   anti-selection 버그로 pool 자체가 왜곡 → native는 참고선으로 격하,
   버그는 수정판(fixedhof)과 병기.
5. **참고연구와의 수치 비교는 배치층 정렬 없이는 무의미하다**: AlphaAgent
   논문의 AR 11%는 top-50/drop-5 롱온리·지수 대비 초과 기준 — 우리 20/20
   롱숏 절대수익과 애초에 같은 단위가 아니었다 → 논문 anchor 셀(A3) 필요.

## 8. 연구질문 정합성

* **Q1·Q2 (탐색 분포·행동)**: backtest와 **무관하게 유지** — trajectory·
  search-QD에서만 분석. 본 설계는 Q1/Q2를 건드리지 않는 것이 미덕이다.
* **Q3 (pool의 QD 구조)**: Common 결합이 무학습이므로 pool 구조(다양성·부호
  일관성·상관)가 성과에 직접 비친다. 결합기 (a)vs(b) 차이 자체가 "부호
  일관성"이라는 구조 특성의 측정이다.
* **Q4 (QD → 성능)**: 종속변수가 (i) 중앙값 성과 (ii) DCS 둘이 되어 "QD
  특성이 성과 **크기**뿐 아니라 배치 **강건성**을 예측하는가"로 강화된다.
  상관분석의 단위는 pool(seed·universe로 n 확보)이며, 셀은 pool 내 상관
  표본이므로 상관분석에는 pool-프로파일 값만 사용한다(유사반복 방지;
  소표본 계층 규칙 — n<3 기술만, 3–4 exploratory, ≥5 CI — 은 v2 노트북
  §10과 동일).

## 9. 의도적으로 하지 않는 것

* **Native end-to-end 완전 재현** — §1.3의 불가능 근거. 배치층 재현(A3)과
  결합 명세 재현(Native 트랙)까지만.
* **격자 확장 유혹** — 리밸런스 주기 스윕, k 스윕, 체결 모형 다양화 등은
  "순위를 바꾼다는 실측 증거"가 나올 때만 버전 업으로 수용.
* **모델 결합기의 본선 편입** — §2.4. 부록/Native 트랙 전용.
* **단일 종합 점수** — 12셀+프로파일을 하나의 스칼라로 합치지 않는다.
  가중치 선택이 또 하나의 자의성이 되기 때문이다. DCS가 유일한 축약이며
  그것도 기술 지표다.

---

## 10. 알려진 한계

1. 격자 축·셀도 결국 우리의 선택이다 — 근거(§6·§7)를 문서화하는 것으로
   자의성을 상쇄하되, 제거하지는 못한다.
2. DCS의 12셀은 독립이 아니므로 통계적 주장 불가(기술 지표).
3. A3(롱온리)의 초과수익은 지수 하락기(2021–24 CSI800 연 −4.6%)에 확대되는
   특성이 있다 — 모든 보고서에 각주 의무.
4. universe(csi800)·benchmark(SH000906)가 참고논문(CSI500/SH000905)과 달라
   논문 anchor 셀도 "동일 배치층, 상이 universe" 비교다.
5. 시장충격·호가스프레드·차입비용은 모형화하지 않는다(비용률 스윕이 근사) —
   롱숏 셀의 공매도 실행 가능성은 특히 낙관적 가정이다.
